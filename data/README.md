# Example data

Both files are generated by the repository itself, so every number in the
top-level README can be reproduced with no download:

```bash
python scripts/forecast.py --save-history data/arrivals.csv \
                           --save-requirement data/requirement.csv
```

| file | what it is |
|---|---|
| `arrivals.csv` | 52 weeks of hourly call volumes — the history the forecast trains on |
| `requirement.csv` | agents needed per hour next week, after Erlang C and shrinkage |

`arrivals.csv` is synthetic on purpose. It carries a weekday and weekend shape,
a slow upward trend, a yearly swell, occasional spike days and overdispersed
noise, which is enough to make forecasting non-trivial and enough to keep the
results reproducible from a seed.

## Using real data instead

Both scripts read CSVs, so nothing here is load-bearing:

```bash
python scripts/forecast.py --history path/to/your_arrivals.csv --column calls
python scripts/solve.py    --requirement path/to/your_requirement.csv --agents 24
```

`arrivals.csv` needs one row per hour in chronological order starting on a
Monday, and a whole number of weeks. `requirement.csv` needs a header and
twenty-four rows, one per hour, with a leading hour column and seven day
columns.

The public reference dataset for this problem is the **Technion SEE Lab**
call-centre archive — a full year of call-by-call records from an Israeli bank,
which is where most published Erlang C work gets its arrival patterns:
<https://see-center.iem.technion.ac.il/databases/DataCenter/>. Aggregate it to
hourly counts and it drops straight into `--history`.

No operational data from any employer appears in this repository.
